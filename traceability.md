# Матрица прослеживаемости требований

**Назначение:** связать бизнес-потребность с пользовательской историей, операцией API, критерием приёмки и способом проверки.  
**Статус:** предложенные требования для учебного кейса; согласование с заинтересованными сторонами ещё не проведено.

Матрица охватывает 13 пользовательских историй и 13 операций из [`event-management-api.yaml`](event-management-api.yaml). Бизнес-контекст, цели, допущения и открытые вопросы описаны в [`business-requirements.md`](business-requirements.md).

## Модель прослеживаемости

`Бизнес-цель / бизнес-требование → User Story → критерий приёмки → операция API → сценарий проверки`

Mock-сервер и коллекция Postman позволяют проверять поведение контракта запрос/ответ. Они не подтверждают наличие производственной бизнес-логики, постоянного хранения данных или контроля параллельных операций.

## Покрытие и ограничения

- В матрице описаны 13 пользовательских историй, сопоставленных с 13 операциями API.
- Для каждой истории указан ожидаемый результат и хотя бы один сценарий проверки.
- Наличие строки в матрице не означает, что требование подтверждено заказчиком или что бизнес-логика реализована.
- Проверки на Prism подтверждают только соответствие запросов и ответов настроенному контракту и примерам.
- До реализации необходимо согласовать открытые вопросы из [`business-requirements.md`](business-requirements.md), включая правила переходов статусов, буфер между активностями, требования к персоналу и поведение при параллельных назначениях.
